# 被动扫描设计与实机验收

## 数据来源

新模块使用 ESP-IDF 的 `esp_wifi_scan_start(config, false)`，并明确设置 `WIFI_SCAN_TYPE_PASSIVE`、隐藏热点可见、每信道 300 ms。不调用 connect，不发送口令尝试，不启用新 AP；不改变地区配置去强行扫描禁用信道。实际上能扫描的信道以 SDK 当前地区设置为准。

完成事件只将状态写入原子变量；主循环读取结果、更新快照、排序和绘制。15 秒未完成则停止并报错。开始前检查剩余堆，初始化失败保留错误状态；低内存检查是提前保护，不能保证 SDK 所有内部分配都成功。

## 资源和状态

- 应用快照最多 64 条；临时 SDK 接收数组也为固定容量，避免把大数组压到 loop 任务栈。
- SDK 在扫描期间仍可能动态分配，不能把有界快照宣传成零分配扫描。
- SDK 结果按 RSSI 排序；接收前 64 条，释放驱动的整个结果列表。快照再按 BSSID 去重、RSSI 降序排序，信号相同按 BSSID 稳定排序。
- 使用 RAM 配置，扫描结果不写入 Flash。
- 完成、停止、超时或失败时注销事件处理器，清除扫描列表并停止/释放自有 Wi-Fi 驱动；不删除共享默认事件循环。
- PMF 观测表独立限制为 64 个 BSSID，按已收帧的峰值 RSSI 保留；不保存原始帧、PMKID 或用户数据。
- 在扫描驱动中启用仅管理帧的接收过滤，回调只解析 Beacon/Probe Response；锁内只更新有界证据，禁止绘制、输出串口或动态分配。完成/停止时冻结证据、禁用并注销接收回调；新扫描清空证据，取消/失败保留旧完成快照。
- 不抢占原版已连接的网络。使用原版工具前停止新扫描；串口命令优先，任何串口命令会取消正在运行的新扫描。
- 扫描过程中先完成或停止再打开结果/图表/导出。失败和取消不会用半成品覆盖上次完成快照。

## 字段和限制

显示 SDK 提供的 SSID、BSSID、信道、RSSI、认证类型、WPS 广播标志及完成时的上电后时间。PMF 从同时被动收到的 Beacon/Probe Response 顶层 RSN 能力字段解析，并按 BSSID 与 SDK 快照关联。未接收到可靠证据时保持未知，详见 `pmf-observation.md`。

信号百分比是 `-100 dBm → 0%`、`-50 dBm → 100%` 的线性换算并限幅，不代表链路质量、吞吐量或距离。信道柱状图仅统计保留的最多 64 个热点，不能表示真实信道利用率。

这是手动刷新快照。单个详情中的 RSSI 不是持续监测曲线；历史趋势尚未实现。SSID 字体只覆盖界面文字与 ASCII，缺字用问号；SDK 不提供完整原始 SSID 长度，因此含 NUL 的名称不能保证无损展示。

## USB CSV

在 115200 波特率串口接收 `REDGUARD_CSV_BEGIN` 和 `REDGUARD_CSV_END` 之间的内容。表头是 `ssid,bssid,channel,rssi_dbm,auth,uptime_ms,pmf,pairwise_cipher_id,group_cipher_id,wps_advertised`。前 7 列顺序保留，后面新增 3 列；套件 ID 为固定 SDK 枚举值，WPS 为 SDK 广播标志的 0/1，0 不证明关闭。PMF 字符串取值见 `pmf-observation.md`。

CSV 中 SSID 以双引号包围并重复内部双引号；所有名称前加单引号，防止电子表格公式执行。控制字符替换成问号。因此这是面向查看的安全导出，不是原始 SSID 字节的无损存档。串口导出是用户主动动作，传输期间可能短暂影响触摸响应；没有写入 SD 或 Flash。没有保存密码。

## 实机验收清单

新增固件未刷入当前开发板；以下项目仍待实际验证：

1. 启动 Logo、中文菜单、上下移动/中选释放/长按和分页。
2. 在本人路由器附近开始被动扫描，正常完成，核对已知 SSID/BSSID/信道。
3. 中途取消、重复开始/停止、15 秒超时及无热点环境；检查触摸响应和错误提示。
4. 列表排序、不同信道过滤、空过滤结果、返回菜单、最末尾选项。
5. 详情字段、隐藏/超长/缺字名称，以及 USB CSV 重新导入表格。
6. 密集环境截断提示与图表范围；确认统计来自保留快照。
7. 进入/退出原版 Wi-Fi 与 BLE 工具，再回到新扫描；用串口命令打断新扫描。
8. 本人路由器设置 PMF 关闭/可选/要求后逐次扫描，核对显示和 CSV；留意地区信道、射频遗漏、MBSSID 非发送配置及未知结果。
9. 多次扫描后记录最低可用堆和任务栈，检查长期增长、重启和屏幕异常。

严格确认无探测请求等行为，需要另一个受控无线抓包设备观察射频流量。代码明确设置被动模式不等于已经完成射频实测。
